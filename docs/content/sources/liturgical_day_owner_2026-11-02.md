# بداية اليوم الطقسي في الكنيسة القبطية الأرثوذكسية وتطبيقها في البرمجيات

## 1. المقدمة والمفهوم الإيماني والطقسي

في الطقس القبطي الأرثوذكسي، يُحسب اليوم الطقسي **من الغروب إلى الغروب التالي**، اقتداءً بالنموذج الكتابي الوارد في سفر التكوين: 
> *"وَكَانَ مَسَاءٌ وَكَانَ صَبَاحٌ يَوْماً وَاحِداً"* (تك 1: 5).

بناءً على ذلك، فإن **صلاة العشية (رفع بخور عشية)** التي تُقام بعد غروب الشمس، تُعتبر رسمياً وطقسياً هي **الافتتاحية والبداية لليوم الطقسي الجديد (اليوم التالي)**، وليست خاتمة لليوم المنقضي.

---

## 2. كيفية حساب اليوم الطقسي (مقارنة بالتقويم المدني)

| وجه المقارنة | التقويم المدني (العادي) | التقويم الطقسي الكنسي |
| :--- | :--- | :--- |
| **بداية اليوم** | منتصف الليل ($12:00\text{ AM}$) | غروب الشمس ($Sunset$) |
| **صلاة العشية** | تُحسب في نفس اليوم تقويمياً | تُحسب على **اليوم التالي** طقسياً |
| **مثال عملي (الجمعة مساءً)** | يُعتبر مساء يوم الجمعة | يُعتبر طقسياً بداية **يوم السبت** |

### تطبيقات عامة على المناسبات:
* **عشية الأحد (تُقام مساء السبت):** تعتبر بداية يوم الأحد، وتُقال فيها ألحان وقطمارس ومزامير يوم الأحد.
* **الأعياد والمواسم:** عشية العيد (التي تُقام في المساء السابق للسيامة أو العيد) هي البداية الفعلية لطقس العيد، ويُقرأ فيها قراءات عشية العيد.

## 3. المنطق البرمجي (Logic) لتطبيقات الأجبية والقراءات (القطمارس)

إذا كنت تقوم بتطوير تطبيق كنسي (أجبية، قطمارس، أو تقويم قبطي)، فإن المنطق الصحيح لعرض الصلوات والقراءات يعتمد على **وقت الغروب** أو على **ساعة محددة ثابته كمعيار**.

### الخوارزمية المقترحة (Algorithm):

1. **تحديد وقت الغروب (Sunset Time):**
   * إما ديناميكياً بحسب موقع المستخدم الجغرافي (GPS / Coordinates).
   * أو تحديد وقت تقريبي ثابت (مثلاً الساعة $5:30\text{ PM}$ أو $6:00\text{ PM}$) كحد فاصل للتيسير.

2. **قواعد العرض (Display Rules):**
   * **قبل الغروب (قبل $6:00\text{ PM}$):**
     * اليوم الطقسي = اليوم الحالي.
     * الصلوات المعروضة: صلوات اليوم الحالي (باكر، ظُهر، غروب، نوم...).
   * **بعد الغروب (بعد $6:00\text{ PM}$):**
     * اليوم الطقسي = **اليوم التالي ($Today + 1\text{ day}$)**.
     * الصلوات المعروضة: **رفع بخور عشية لليوم التالي** + قراءات قطمارس اليوم التالي + سنكسار اليوم التالي.

## 4. مثال بروجرامي توضيحي (Pseudo-code)

```javascript
// تحديد ما إذا كان الوقت الحالي بعد الغروب
function getLiturgicalDate(currentDate, sunsetTime) {
    let liturgicalDate = new Date(currentDate);

    // إذا كان الوقت الحالي بعد وقت الغروب
    if (currentDate.getHours() >= sunsetTime.getHours()) {
        // الانتقال لليوم الطقسي التالي
        liturgicalDate.setDate(liturgicalDate.getDate() + 1);
    }

    return liturgicalDate;
}

// الاستخدام
const now = new Date(); // مثلاً: الجمعة 7:00 مساءً
const estimatedSunset = new Date(); 
estimatedSunset.setHours(18, 0, 0); // 6:00 مساءً

const currentLiturgicalDate = getLiturgicalDate(now, estimatedSunset);
// النتيجة: التطبيق سيعرض قراءات وعشية يوم "السبت"
```

## 5. توصيات لتحسين تجربة المستخدم (UX) في التطبيق

1. **زر تبديل يدوي (Manual Toggle):** 
   * يفضل دائماً إتاحة خيار للمستخدم للتنقل بين "اليوم التقويمي" و"اليوم الطقسي"، أو وضع زر: *(عرض قراءات غداً / عشية اليوم)*.
2. **توضيح التنبيه للمستخدم:**
   * عند فتح التطبيق بعد الغروب، يُفضل عرض تنبيه بسيط أو عنوان واضح: 
     > *"تعرض الآن: عشية وقراءات يوم [اسم اليوم التالي] ([التاريخ القبطي/المدني لليوم التالي])"*.
3. **التعامل مع صلاة السُّتْر ونصف الليل:**
   * صلاة نصف الليل وتسبحة نصف الليل تتبعان اليوم الجديد (تُصليان في الهزيع الأول/الثاني/الثالث من الليل التابع لليوم الجديد).

---

## 6. الخلاصة

نعم، **صلوات العشية تُحسب على اليوم التالي**. وبالتالي، فإن التصميم الأصوب والأكثر دقة لأي تطبيق كنسي قبطي هو **عرض قراءات وصلوات وعشية غداً بمجرد حلول الغروب (أو الساعة السادسة مساءً كحد تقريبي)**.
